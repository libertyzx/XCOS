### 影响面

| 用户 `fIdle` 的写法 | 后果 |
| --- | --- |
| `__WFI()`（示例工程 `Examples/CortexM3_Test/Code/Main/main.c` 的 `Idle()` 即此类，**不使用提示值**） | 基本无害（任何中断都会唤回）⇒ **示例工程不受影响** |
| 按提示值进低功耗且 Tick 停走（低功耗定时器/RTC 唤醒） | **设备"假死"**：本该 1 个 tick 后醒，实际睡 ≈49.7 天（WDT 关掉 = 变砖级） |
| 按契约注释 `XC_Time_TickSet(GetTick() + IdleTick)` 回填 | 系统时钟跳变 ⇒ 触发时间调度"整表回绕处理" ⇒ **所有延时任务被集体提前唤醒**（随后自恢复） |

> 触发概率随 `XC_CFG_TICKS_PER_SEC` **急剧上升**：1 kHz 需"窗口 ≥2 ms"（近似不可达）→ 10 kHz 需 ≈200 µs（**可达**）→ 100 kHz 需 ≈20 µs（**易命中**）。
> 而高频档恰恰是"tick 级短延时"最常用、即"最早唤醒恰在 1 tick 内"最容易成立的场景。
