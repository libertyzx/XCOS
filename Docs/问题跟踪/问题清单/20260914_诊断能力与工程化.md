### B1 帧栈越界 → 静默复位（无任何错误上报）

**状态**：✅ **已解决（已修复，2026-09-14）** —— 采用**方案 1（错误钩子）**：新增公共头 `Code/Inc/XC_Diag.h`（错误码 `XC_ErrCode_t` + 用户钩子 `XC_Err_Hook` + 上报宏 `XC_Err_Report`）与开关 `XC_CFG_ERR_HOOK`（**默认关，0 代码/0 RAM，且无需实现钩子**）；越界分支在**降级之前**上报，钩子内可读到现场（`CorDepth`/`CorDepthMax`）。**方案 2（`LastError` 字节）本次不采用**（用户决策：只加钩子；字段方案可作为将来备选，本次未动 TCB 布局）。

**证据**：`XC_Task.c:71-74`（`PushFrame` 越界保护：`CorDepth >= CorDepthMax` ⇒ `XC_Task_HandleReset` 后 return）；`XC_Task.c:144-157`（复位会清断点/清栈 ⇒ 任务**从头开始**）。
**影响**：调用 `XC_Cor_Call` 未配帧栈、或嵌套过深时，任务"莫名从头运行"；功能异常但**无日志、无计数**，现场极难定位（尤其量产）。
**方案**：
1. 加**错误钩子/统计**（可选宏，默认关闭以免增开销）：
   ```c
   #ifdef XC_CFG_ERR_HOOK
   extern void XC_Err_Hook(struct XC_TaskCB_tag* phTCB, uint8_t ErrCode);
   #define XC_ERR_FRAME_OVERFLOW (1U)
   #endif
   ```
   在越界分支调用 `XC_Err_Hook(phTCB, XC_ERR_FRAME_OVERFLOW)`；
2. 或在 TCB 的 `CorState` 旁增加 1 字节 `LastError`（现有尾部 padding 可容纳，**RAM +0**），并提供 `XC_Task_GetLastError()`。
**验证**：故意不配帧栈就 `XC_Cor_Call` ⇒ 钩子被调用 / `LastError` 非 0。

> **2026-09-14 诊断模块化**：本项实现已迁入 `Code/Inc/XC_Diag.h` / `Code/Src/XC_Diag.c`（`XC_Err.h` 并入后删除；内核侧仅保留埋点调用）；关档体积仍与改前一致（`XC_Diag.o` = 0 B）。

### B3 无"任务状态 ↔ 所在表"一致性自检

**状态**：✅ **已解决（已修复，2026-09-14）** —— 按用户决策**作为"调试函数"保留并写明文档/注释**：新增结果枚举 `XC_ChkResult_t` 与 `XC_Diag_CheckInvariants(phXCOS)`（**仅 `XC_CFG_DEBUG_CHECK` 打开时编译**）；它是**只读检查**（不改状态、不改内核行为、不会自动调用），失败返回**第一个失败项编号**；发布档默认关闭 ⇒ **0 代码 / 0 RAM / 0 耗时**。

**背景**：内核多处依赖不变量（游离=自环；状态与表一致；每任务最多在一张表），但**没有运行期校验**；历史上两个缺陷（僵尸状态、误唤醒）都属于该不变量被破坏。
**方案**：提供仅在 `XC_CFG_DEBUG_CHECK` 下编译的自检函数，在 idle 或指定点抽查：
```c
void XC_Diag_CheckInvariants(XC_OSHandle_t phXCOS);
/* 检查项:
 *  1) 遍历就绪/时间/溢出/阻塞四表: 每个节点自环与否符合预期;
 *  2) TaskState 与所在表匹配(READY↔Ready, BLOCKED/SUSPEND↔Time/Blocked, RUN↔游离);
 *  3) 同一 TCB 不在两张表中(节点地址去重);
 *  4) TaskNum 与实际节点总数一致;
 *  任一项失败 => XC_Err_Hook(...) 或死循环便于定位。 */
```
**验证**：把现有两个复现用例（僵尸状态、误唤醒）跑在 debug 自检下，应能在**更早**的时刻报出不一致。

> **2026-09-14 诊断模块化**：自检实现已迁入 `Code/Inc/XC_Diag.h` / `Code/Src/XC_Diag.c` 并更名为 `XC_Diag_CheckInvariants`；内核侧不再包含自检代码（`XC_Sch.o` 关档仍为 600 B = 改前）。

### B4 无运行统计（每任务运行次数 / 最长执行时间）

**状态**：✅ **已解决（已修复，2026-09-14）** —— 按用户决策**本版本实现**，采用**方案 A（TCB 字段）**：开关 `XC_CFG_TASK_STATS`（默认关 ⇒ 字段与统计代码都不编译，**0 代码/0 RAM**）；打开后 TCB 追加 `RunCnt`（`uint32_t`，饱和计数）与 `MaxRunTick`（`XC_Tick_t`），由调度器在每个"调度槽"两端累计，提供 `XC_Diag_GetRunCnt` / `XC_Diag_GetMaxRunTick` / `XC_Diag_ClrRunStats` 查询与清零。

**背景**：协作式内核里"某任务执行多久"直接决定系统响应（无优先级），但框架不提供任何观测手段；只能靠用户自己打点。
**方案**：可选宏 `XC_CFG_TASK_STATS`（默认关）：TCB 加 `RunCnt`（复用 padding 或 +1B）、`MaxRunTick`；调度器在运行前后取 `XC_Time_GetTick()`（Tick 粒度 1ms，够用）记录极值。
**收益**：直接回答"哪个任务拖慢了通知处理"，与 `Docs/Skill/MDK_Sim_Agent_Skill.md` 的周期测量互补（一个看最坏时延，一个看指令数）。

**实施设计（2026-09-14 评审记录；**本版本已落地**，实测见文末「实施结果」）**

*1) 测量点（现有实现坐标）*：`XC_Sch_Start` 主循环的"运行块"——
- **起点**："取任务/摘表/置 RUN"之后、`phTCB->fTask(phTCB)` **之前**；
- **终点**："同轮切父" `while(CorState==DONE && CorDepth>0)` 之后、**归位（插回就绪表）之前**；
- 语义：一次"**调度槽**"= 从表首摘出到让出（含同轮切父的父层）⇒ 最贴近"这个任务占了多少 CPU"；
- 差值用**无符号减法** `End - Start`（回绕安全，与 `XC_Time_CheckTimeout` 同思路）。

*2) 起始时刻**不需要**进 TCB*：协作式非抢占 ⇒ 同一时刻只有一个任务在跑 ⇒ 用调度器**局部变量**保存 `RunStart` 即可（0 RAM/任务）。

*3) 每任务存什么（RAM 账，TCB 现为 44 B）*

| 方案 | TCB 增量 | 100 任务 RAM | 能回答的问题 |
| --- | --- | --- | --- |
| **A. TCB 加字段**（条目原方案） | `RunCnt`(uint16) + `MaxRunTick`(4B) ⇒ **44→48 B（+4）** | **+400 B** | 每任务"运行次数 + 最长一次耗时"（可查询） |
| **B. 只记全局最坏** | TCB 不加；调度器加 `MaxRunTick` + `pWorstTCB` ⇒ **全局 +8 B** | **+8 B** | "最坏是谁、多久"（定位"谁拖慢了我"够用） |
| **C. 钩子式（0 RAM）** | TCB 不加；`XC_RunStatHook(phTCB, Elapsed)`，统计存用户侧 | **+0 B** | 最灵活（日志/环形缓冲/上位机），与 B1 钩子风格一致 |
| **D. 用户数组 + 任务 id** | TCB 加 `Id`(1B) ⇒ +4 B，用户提供 `stats[N]` | +4/任务 + 用户数组 | 可查询/可清零，但需用户管理数组 |

> 推荐：要"每任务可查询"选 **A**；要零 RAM / 要给上位机选 **C**；只想知道"谁最慢"选 **B**（最省）。

*4) 精度与边界（必须写入文档）*
- 默认 1 ms 时基 ⇒ **短于 1 tick 的任务记到 0**（量化误差 ±1 tick）；要更细用**计数器模式**（`XC_SYS_TICK_COUNT` 指向硬件计数器）或高频档（`>1000Hz` 走 us 时基）；
- 测量**包含运行期间的 ISR 时间**（tick 会被 ISR 推进）⇒ 这是"**调度槽耗时**"，不是"纯任务指令数"；要指令级请用 MDK 仿真周期测量（互补）；
- `RunCnt` 宽度：uint16 会在 **65535 次**回绕 ⇒ 需长跑统计就选 uint32（+4 B/任务）；
- 生命周期：建议"**注册/移除时清零、`XC_Task_Reset` 保留**"（Reset 多为排障场景，清零等于丢证据）；
- 让出/阻塞期间**不计时**（测量在调度槽内闭合）。

*5) 建议 API（仅开关打开时声明）*
```c
uint32_t        XC_Diag_GetRunCnt(XC_TaskHandle_t phTCB);      /* 运行次数 */
XC_Tick_t       XC_Diag_GetMaxRunTick(XC_TaskHandle_t phTCB);  /* 最长一次耗时(Tick) */
XC_Tick_t       XC_Task_GetLastRunTick(XC_TaskHandle_t phTCB); /* 最近一次(可选) */
void            XC_Diag_ClrRunStats(XC_TaskHandle_t phTCB);    /* 清零(便于测"某段时间") */
XC_TaskHandle_t XC_Sch_GetWorstTask(XC_OSHandle_t phXCOS);     /* 仅方案 B */
```

*6) 代码骨架（以方案 A 为例）*
```c
/* XC_Config.h */
#ifndef XC_CFG_TASK_STATS
#define XC_CFG_TASK_STATS (0U)   /* 0=关(默认, 0 RAM/0 Flash); 1=开 */
#endif

/* Internal/XC_TypeInternal.h: TCB 尾部(仅开关打开时存在) */
#if (XC_CFG_TASK_STATS != 0)
    volatile uint16_t RunCnt;      /* 主上下文单写者(调度器) */
    XC_Tick_t         MaxRunTick;  /* 仅单调增大 */
#endif

/* XC_Sch.c: 运行块包裹(建议抽成两个内部函数, 便于宿主用例直接验证) */
void XC_Diag_RunStatsBegin(XC_OSHandle_t phXCOS);  /* 记录调度槽起始 Tick */
void XC_Diag_RunStatsEnd(XC_TaskHandle_t phTCB);   /* RunCnt++; MaxRunTick = max(...) */
```
- 统计字段是**新增共享字段** ⇒ 必须在 `Docs/XCOS.md`「并发模型与字段所有权」矩阵登记（写者=主循环/调度器；模型=主上下文，无 RMW 竞争），并在头文件加 `[并发]` 注释。

*7) 验证方式（可测性）*
- 框架支持 `XC_SYS_TICK_COUNT` 宏覆盖 ⇒ 宿主用例把它指向**测试变量**（`#define XC_SYS_TICK_COUNT g_statTick`），任务体内把 `g_statTick += 5`，调用同款 `RunStatsBegin/End` ⇒ 断言 `RunCnt==1`、`MaxRunTick==5`；
- 再加"长任务 + 短任务"轮转 ⇒ 断言两者 `MaxRunTick` 可区分；
- **关档必须 0 影响**（`XC_Task.o` / 镜像 `Code` 与改前一致），开档记录对象级/镜像级增量；
- 回归：A1/A2/B1/B3 用例两档全跑。

*8) 与现有诊断体系的分工*

| 手段 | 回答 | 开销 |
