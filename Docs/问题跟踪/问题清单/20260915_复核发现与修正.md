## 六、规则固化（R16：断言 vs 返回值校验的边界，已落文档）

**背景**：R1 的争议暴露"断言 / 返回校验"在多处**同时实现同一条件**（重复强制点）⇒ 用户确立并细化规则如下
（已写入 [`Docs/XCOS.md`](../../XCOS.md)「断言」R1~R7 表，并同步 `XC_Config.md`、`Skill` 陷阱 21、`架构概览`）。

| 规则                | 内容                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| **R1 互斥**         | 同一形参 + 同一失效条件 ⇒ **只允许一个强制点**（断言 或 返回码，**不得叠加**）                 |
| **R2 允许并存**     | 不同形参 / 同一形参的**不同**条件 ⇒ 可混用（两条独立契约）                                     |
| **R3 禁止部分重叠** | 复合 `if` 中不得再 `OR` 已被断言覆盖的子条件                                                    |
| **R4 方向判据**     | **参数合法性/编程错误** ⇒ 断言（违背 = 未定义行为）；**运行期前提 / 契约承诺的结果** ⇒ 返回码 |
| **R5 归属层级**     | 契约写在**最小公共入口**；包装函数只断言自己新增的契约                                          |
| **R6 宏例外**       | 宏类 API 无返回路径 ⇒ 只能断言（文档写明"调用方保证"）                                         |
| **R7 跨 API 一致**  | 同类失效（如参数 `NULL`）在各 API 间必须**一致选择**                                            |

**本内核选择（方向 A：性能优先）**：参数合法性 = 断言（发布档 0 开销）／运行期前提与承诺结果 = 返回码。

**审计结果（2026-09-15，全仓 26 处断言 × 13 处参数/状态 `if`）**：

| 违规 | 位置                                          | 形态                                           | 处置                                          |
| ---- | --------------------------------------------- | ---------------------------------------------- | --------------------------------------------- |
| V1   | `XC_Task_Reg`（`fTask == NULL`）              | 完全重叠（R1 引入）                            | 回退 `if`，留断言                             |
| V2   | `XC_Task_RegExt`（帧栈参数组合）              | 完全重叠                                       | 删 `if`，留断言                               |
| V3   | `XC_Task_SetCorStack`（同上）                 | 完全重叠                                       | 删 `if`，留断言                               |
| V4   | `XC_Task_Add`（复合条件里的 `fTask == NULL`） | **部分重叠**（R3）                             | 拆分条件，只判表满                            |
| V5   | `XC_Diag_CheckInvariants`（`phXCOS == NULL`） | 完全重叠，但**方向相反**（属"承诺报告的结果"） | **删断言**，留 `if(...) return XC_CHK_HANDLE` |

**遗留（低危，未处理）**：`XC_Task_RegExt` 的 `phTCB`/`phXCOS`/`fTask` 三条断言与 `XC_Task_Reg` 重复 ——

修正后三通道 **ALL PASS**（PASS 16 / FAIL 0 / SKIP 3）。**教训**：删除既有校验时，必须全仓检索**用例/文档对该校验行为的依赖**（本次即由回归用例第一时间拦住）。
