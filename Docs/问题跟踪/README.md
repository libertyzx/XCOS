## 约定

1. **问题清单（按「批次 + 类别」汇总）**：文件名 = **`<批次日期>_<类别>.md`**（已存在 `20260914_*` / `20260915_*` / **`20260916_*`** 批次，**按文件名即可排序**）；`问题清单/README.md` 是**索引**（分类表 + 条目状态一览）；**新增问题**默认**新建** `<提出日期>_<类别>.md`（同一类别可存在多个批次文件；仅"同批次内追加"才写入该批次文件），并在索引表补一行；条目到达终态时在标题与索引表标注 `✅/⛔`；
2. **修正方案**：每项一个目录 `修正方案/<日期>_<主题>/`，目录内固定 `修正方案.md`；附件按需（`测试/`、`*.patch`）；**长周期专题**另加 `README.md` 作追踪入口；
3. **状态可见**：`修正方案/` 下每项都要能一眼看出状态（`已实施` / `未采用` / `追踪中`），并把对应清单编号写进方案文档；
4. 测试用例命名：`<日期>_<主题>_<类型>.c`（`复现测试` / `回归测试` / `综合测试` / `新旧代码对照_sim`；MDK 仿真通道另有 `_仿真测点.c` + `sim.ini`）；
5. 文档内引用一律使用**仓库相对路径**（如 `Docs/问题跟踪/…`）；历史文档保留原文，仅统一更新其中的路径引用。

## 交叉引用

* 问题清单 ↔ 修正方案 **双向引用**：汇总文件内的条目指向方案目录；方案文档注明对应条目编号（如 `A1`）；
* **状态以各问题文件内标注 + `问题清单/README.md` 综合表为准**（本 README 只做入口、约定，以及"**整批是否已解决**"的标注）；
* 性能数据原始出处：[`修正方案/20260911_O3_唤醒任务表优化/修正方案.md`](./修正方案/20260911_O3_唤醒任务表优化/修正方案.md)。
