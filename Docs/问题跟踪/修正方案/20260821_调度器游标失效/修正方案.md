## 1. 问题概述

### 1.1 现象

在特定调用组合下，调度器会发生以下异常（按严重程度递增）：

1. **被挂起的任务被错误调度运行**：任务状态被从 `SUSPEND` 覆写为 `RUN/READY`；
2. **调度器插入锚点被污染**：`phXCOS->pPrevReadyNode` 指向阻塞表节点，后续所有"唤醒/新增任务插入就绪表"操作位置错误，**链表结构被破坏**；
3. **访问越界崩溃**：调度器把链表根节点当任务 TCB 解引用，实测触发 `0xC0000005`（访问冲突）。

### 1.2 触发条件（须同时满足）

1. 任务 A 运行期间调用 `XC_Task_Suspend`/`XC_Task_Remove`（或中断中调用），目标是**就绪表中的另一任务 B**；
2. **B 恰好位于 A 在就绪表中的"后继"位置**（即调度器跨轮游标 `pIterator` 当前指向的节点）；
3. 就绪表任务不少于 2 个。

### 1.3 严重程度

**高**。触发即导致挂起任务被运行、链表污染，严重时崩溃。触发条件虽较苛刻（"目标是游标位置"这个精确组合），但一旦触发无恢复路径。

## 2. 根因分析

### 2.1 调度器现有机制（V2.1.0 跨轮游标）

```c
/* XC_Sch_Start 当前实现（XC_Sch.c 220-241 行）*/
pIterator = XC_List_GetListStartNode(&phXCOS->ReadyList); // 游标初始指向表首
for(;;) {
    if(XC_List_ListValid(&phXCOS->ReadyList)) {
        if(XC_List_ReachEndNode(&phXCOS->ReadyList, pIterator)) {
            pIterator = pIterator->pNext;                  // 到根则从头
        }
        phXCOS->pPrevReadyNode = pIterator->pPrev;         // 记录插入锚点
        phTCB                  = XC_LIST_TO_TCB(pIterator);
        pIterator              = pIterator->pNext;         // ★ 运行前推进游标到后继
        phTCB->TaskState       = XC_TASK_RUN;
        phTCB->fTask(phTCB);                               // 运行任务
        ...
    }
    ...
}
```

两个关键设计事实：

- **游标在任务运行前已推进到"当前任务的后继"**（`pIterator = pIterator->pNext` 在 `fTask` 之前）；
- **任务运行期间，任务节点仍在就绪表中**（调度器只跳过它，未摘除）——因此任务可被外部 API 移动。

### 2.2 失效链路（A 运行中挂起后继 B）

```
就绪表:  Root → … → A → B → C → …
                          ↑
              游标已推进到 B（A 运行前, fTask(A) 之前）
A 运行 XC_Task_Suspend(B) → B 移入阻塞表
就绪表:  Root → … → A → C → …
                          ↑
              游标仍指向 B —— 但 B 现在在【阻塞表】！
```

下一轮主循环继续使用这个"悬空游标"：

1. `pPrevReadyNode = B->pPrev` → 得到的是 **B 在阻塞表里的前驱（阻塞表根）** → 锚点被污染；
2. `phTCB = B` → **挂起任务被当就绪任务运行**，状态被覆写；
3. 再下一轮：游标顺着 B 在阻塞表的链接走到阻塞表根 → `XC_LIST_TO_TCB(阻塞表根)` → **越界崩溃**。

若目标是 `Remove`（节点被 `XC_List_Remove` 初始化为自环）：游标指向自环节点，`ReachEnd` 永远判不到根 → 遍历错乱/死循环。

### 2.3 为什么"运行前推进游标"本身是必要的

游标推进到后继是为了规避**"当前任务自身被移动"**——任务运行中 Delay/Suspend/Remove 自身是最常见操作，若游标停留在当前任务，自身一移走游标就悬空。原设计选择了"推进到后继"，但**未考虑后继也可能被外部移动**。

### 2.4 复现证据（已实测）

- 测试：`Reg(B); Reg(A); Reg(C)`（逆序插表首 → 就绪表 `Root→C→A→B`），A 运行 `Suspend(&gB)`；
- **旧游标逻辑**：挂起任务 B 被运行（`b_c=1`，状态被覆写）；继续运行即崩溃（`0xC0000005`）；
- **方案 A 逻辑**：`b_c=0`（B 从未被调度），B 保持 `SUSPEND`，调度稳定。

## 3. 版本溯源

| 版本            | 提交                          | 索引防护                          | 游标位置         | 有本 bug   |
| --------------- | ----------------------------- | --------------------------------- | ---------------- | ---------- |
| V1.0            | `9ce0e3d`                     | 有（`XCSch_ListNodeRemove` 回退） | 指向当前任务     | 否         |
| V2.0 开发早期   | `80f4516`/`cd052cb`           | 有                                | 指向当前任务     | 否         |
| **V2.0 正式版** | **`8b70b10`（重构更新V2.0）** | **重构时删除**                    | 运行前推进到后继 | **是**     |
| V2.1.0 当前     | `c3180e8`+                    | 无                                | 运行前推进到后继 | 是（继承） |

**结论**：本 bug 由 **V2.0 正式发布时的调度器重构引入**——同时改变了三处机制：

1. 游标从"指向当前任务"改为"运行前推进到后继"；
2. 删除 `XCSch_ListNodeRemove` 的"索引回退"防护；
3. 阻塞从"运行后统一处理（Blocked 标志）"改为"运行中立即移表"。

**V2.0 重构的动机**（修复 V1.0 缺陷）：V1.0 的"延迟阻塞"机制在"任务运行中 Delay 后被外部挂起"时，运行后 `BlockedSched` 会对已不在就绪表的任务误操作（把挂起任务错移成延时）+ 状态被无条件覆盖。改为"运行中立即移表"后修复了该问题，但引入了新的游标隐患。

## 4. 修复方案（方案 A：取走任务 + 自环判定）

### 4.1 设计思想

**消除"跨轮游标"这个概念**：调度器每轮从就绪表**首节点**取任务（摘除、游离化）；运行结束后用"**节点是否自环**"判断任务归属：

- **自环（游离）** = 运行期间没有任何 API 移动它（`Yield`/`Leave`/直接 return）→ 移回就绪表尾（轮转）；
- **非自环** = 已被 Delay/Suspend/Reset/唤醒 API 移入对应表 → 调度器不干预。

> 与主流 RTOS（FreeRTOS/RT-Thread）的"取队首 + 让出移队尾 + 无跨轮游标"同构。

### 4.2 新主循环完整代码

```c
/**
 * [用户] 调度器启动(阻塞运行, 永不返回)
 *
 * 方案 A: "取首节点游离化 + 自环判定归位"
 * ---------------------------------------------------------------
 * 每轮流程:
 *   取任务: ListValid 锁外判断(中断仅通知类, 只加不减 -> 判断非空后不会变空);
 *              锁内从【首节点】摘取任务, 使其【游离】(节点自环)。
 *       - 不用跨轮游标: 任务运行期间外部 API(其他任务 Suspend/Remove/Reset 等)
 *         可安全移动任意任务, 不影响调度位置(下一轮从表首重新取);
 *       - 摘除后节点自环 = "游离"标记: 运行结束后据此判断任务该回哪个表。
 *   运行(锁外): 执行任务函数; 嵌套则同轮切父; 顶层完成回落 READY。
 *       - 锁外运行: 任务执行期间中断可正常处理(SendNotify 直接唤醒等);
 *   归位(锁内): 若任务仍游离(运行中没被任何 API 移表, 即 Yield/Leave/直接return),
 *       则插回就绪表尾(轮转); 若已被 API 移入时间表/阻塞表/就绪表(非自环)或已
 *       移除(VOID), 则保持所在位置, 调度器不干预。
 * ---------------------------------------------------------------
 * 锁的唯一目的: 取任务/归位的链表操作 与 中断 SendNotify(Lock=0 直接 MoveToReadyList)
 *               的并发互斥。中断中仅通知类 API(XC_Task_SendNotify)与 Tick 读取/递增
 *               可调用(挂起/恢复/移除/复位等链表操作 API 不可在中断中调用);
 *               若未来出现"中断误用挂起"等, 须在对应 API 层加 Lock 检查(SendNotify 模式),
 *               而非依赖调度器取任务锁(取任务锁防不住 API 层的误用)。
 * 公平性: 让出任务插表尾 -> 严格 Round-Robin(每个任务每轮运行一次);
 * 唤醒及时性: MoveToReadyList 插就绪表首 -> 唤醒任务下轮第一运行。
 */
void XC_Sch_Start(XC_OSHandle_t phXCOS)
{
    uint8_t         Trigger;      // 事件生产者快照(用于检测异步事件)
    XC_TaskHandle_t phTCB;        // 当前取到的任务 TCB(取任务块内使用)
    XC_Tick_t       Tick;         // 空闲休眠时间计算用

    for(;;) {
        /* ---------- 取任务 ---------- */
        /* ListValid 锁外判断: 中断仅通知类(只加不减) -> 判断非空后不会变空, 不会取到根节点 */
        if(XC_List_ListValid(&phXCOS->ReadyList)) {
            XC_Core_Lock(phXCOS);                     // 锁: 保护取任务链表操作 vs 中断 SendNotify 并发
            phTCB = XC_LIST_TO_TCB(XC_List_GetListStartNode(&phXCOS->ReadyList));  // 表首节点 = Root->pNext
            XC_SCH_TAKE_FIRST(phTCB);         // ★ 摘除: 节点自环 => 游离标记
                                                      //   运行中任何 API 移动它都会从自环摘除并插入目标表
            phTCB->TaskState = XC_TASK_RUN;           // 任务状态: 运行
            XC_Core_Unlock(phXCOS);                   // 解锁: 运行阶段中断可正常直接操作

            /* ---------- 运行(锁外) ---------- */
            phTCB->fTask(phTCB);                      // 恒调当前层(顶层或子层); 运行中任务可能:
                                                      //   - Yield/Leave: 节点保持游离(自环);
                                                      //   - Delay/Suspend/Reset/外部操作: 节点被移入对应表(非自环)。
            /* 同轮切父: 当前层完成(DONE)且栈非空时, 弹帧并立即运行父层 */
            while((phTCB->CorState == XC_COR_DONE) && (phTCB->CorDepth > 0U)) {
                XC_Task_PopFrame(phTCB);              // 出栈: 恢复父层入口+返回点
                phTCB->fTask(phTCB);                  // 同轮切父: 运行父层(可能再次 DONE 继续弹帧)
            }
            /* 顶层 DONE 回落: 顶层完成(无嵌套)后任务让出, 状态回落到就绪,
             * 避免"任务在就绪表却报 RUN"的状态不一致 */
            if((phTCB->CorState == XC_COR_DONE) && (phTCB->CorDepth == 0U)) {
                phTCB->TaskState = XC_TASK_READY;
            }
            /* ---------- 归位(锁内): 游离判定 ---------- */
            /* 判定: 任务未被移除(VOID) 且 节点自环(游离)。
             *   自环   = 运行期间没有任何 API 移动它 -> Yield/Leave/直接return, 需插回就绪表;
             *   非自环 = 已被 Delay/Suspend/Reset/唤醒 API 移入对应表 -> 不干预。 */
            if((phTCB->TaskState != (uint8_t)XC_TASK_VOID) &&
               (phTCB->ListNode.pNext == &phTCB->ListNode)) {
                XC_Core_Lock(phXCOS);                 // 锁: 插回是链表写操作, 防中断 SendNotify 并发
                XC_SCH_PUT_TAIL(&phXCOS->ReadyList, phTCB);  // 插就绪表尾(轮转)
                XC_Core_Unlock(phXCOS);
            }
        }
        /* 就绪表空: 直接跳过, 进入时间/事件/空闲处理 */

        XC_Sch_TimeSched(phXCOS);                     // 时间调度: 处理时间表/溢出表到期任务
        /* 事件调度: 中断中 SendNotify 等异步登记(EventProduced++), 此处统一处理 */
        Trigger = phXCOS->EventProduced;              // 快照生产者计数
        if(Trigger != phXCOS->EventConsumed) {        // 有新事件才处理
            phXCOS->EventConsumed = Trigger;          // 更新消费者计数(一次性消费)
            XC_Sch_EventSched(phXCOS);                // 唤醒等待通知的任务
        }
        /* 空闲处理: 就绪表空时计算"距最近唤醒的 Tick"并回调 fIdle */
        if((XC_List_ListValid(&phXCOS->ReadyList) == 0) && (phXCOS->fIdle != NULL)) {
            Tick = XC_Time_GetTick();                 // 当前 Tick
            if(XC_List_ListValid(&phXCOS->TimeList))  // 时间表有节点: 取时间表首节点唤醒时刻差
                Tick = XC_Sch_GetNextTaskWakeupTick() - Tick;
            else if(XC_List_ListValid(&phXCOS->TimeOverflowList))  // 仅溢出表有节点: 取溢出表首节点
                Tick = XC_LIST_TO_TCB(XC_List_GetListStartNode(&phXCOS->TimeOverflowList))->TaskWakeupTick - Tick;
            else                                      // 两表皆空: 按最大时间休眠
                Tick = ~0U;
            phXCOS->fIdle(phXCOS, Tick);              // 回调空闲处理(可休眠系统)
        }
    }
}
```




### 4.3 游离判定原理（自环 = "最后一次移动它的 API"留下的指纹）

| 运行中发生了什么                | 节点状态                 | 调度器动作              |
| ------------------------------- | ------------------------ | ----------------------- |
| `XC_Cor_Yield()`                | 自环（没移表）           | 插回表尾                |
| `XC_Cor_Leave()`（顶层完成）    | 自环                     | 置 READY + 插回表尾     |
| 直接 return                     | 自环（TaskState 仍 RUN） | 插回表尾                |
| `XC_Cor_DelayTick()`            | 非自环（时间表）         | 不动                    |
| `XC_Cor_Suspend()`/外部 Suspend | 非自环（阻塞表）         | 不动                    |
| `XC_Cor_Reset()`                | 非自环（已被移到就绪表） | 不动                    |
| `XC_Cor_Remove()`               | VOID + 自环              | 不插回（显式排除 VOID） |

> **2026-09-16 变更**：`XC_Task_HandleRemove` 出表后把节点置 `NULL`（**不再保留"自环"**）⇒ 归位判据改为**仅判"自环"**
> （`XC_Sch.c` 归位处：锁外快判 + 锁内复判）。本表 `XC_Cor_Remove()` 一行的"显式排除 VOID"表述已被取代，**其余各行不变**。

### 4.4 关键场景推演

**场景 1：本 bug（A 挂起后继 B）**

```
就绪表: Root→C→A→B（Reg B,A,C）
轮1: 摘 C → 运行 C(Yield) → 游离 → 插表尾 → Root→A→B→C
轮2: 摘 A → A 运行 Suspend(B): B 摘出就绪表→插阻塞表(非自环); Root→C
     A Yield → 游离 → 插表尾 → Root→C→A
轮3: 摘 C → ... → B 从未出现在就绪表 → 永不调度 ✓
```

**场景 2：外部 Suspend 当前任务（V1.0 场景 A 的旧 bug）**

```
轮: 摘 A(游离) → 运行 A → 中断 Suspend(A): A 从自环摘除→插阻塞表(非自环, SUSPEND)
    A 继续运行, Yield 把状态覆盖为 READY
    ★ 节点非自环 → 调度器不插回 → 挂起生效 ✓（自环判定天然免疫旧 bug）
```

**场景 3：就绪表仅一个任务 / 空**

```
单任务: 摘 A → 就绪表空 → A Yield → 游离 → MoveNodeAfter(Root->pPrev=Root, A) → Root→A ✓
空表:   不取任务 → 空闲处理 ✓
```

### 4.5 锁模型

| 操作                      | 持锁          | 原因                                  |
| ------------------------- | ------------- | ------------------------------------- |
| 摘任务 / 插回             | 是            | 防中断并发改就绪表                    |
| 运行 fTask                | 否            | 中断可正常处理（SendNotify 直接唤醒） |
| 任务内 Delay/Suspend 移表 | 各 API 自持锁 | 不变                                  |

### 4.6 公平性与唤醒及时性

- **公平性**：让出任务插表尾 → 严格 Round-Robin；
- **唤醒及时性**：`MoveToReadyList` 插就绪表首（下轮第一运行）。

## 5. 性能优化（特化内联宏）

### 5.1 瓶颈定位

方案 A 每轮额外开销集中在两次通用链表函数调用（`XC_List_Remove` + `XC_List_MoveNodeAfter`），各含函数调用开销（约 8-12 周期）。

### 5.2 利用不变量特化

- 取表首：**表首节点前驱恒为 Root** → 摘除省读 `pPrev`；
- 插表尾：**任务必游离（自环）** → 无需先摘除；**表尾的 `pNext` 恒为 Root** → 省读。

```c
/* =====================================================================
 * 摘就绪表首节点(内联宏, 无函数调用, 无临时变量, 单参数)
 * ---------------------------------------------------------------------
 * 输入: phTCB = 就绪表首任务 TCB(由调用处先取, 宏内不再取)
 * 说明: 等价于 XC_List_Remove 内联展开(4 步链表操作);
 *       调用处先取表首任务再调本宏:
 *         phTCB = XC_LIST_TO_TCB(XC_List_GetListStartNode(&phXCOS->ReadyList));
 *         XC_SCH_TAKE_FIRST(phTCB);   // 摘除: 游离化(自环)
 * 步骤:
 *   pNext->pPrev = pPrev                  // 摘除: 第二节点前驱 = Root
 *   pPrev->pNext = pNext                  // 摘除: Root 后继 = 第二节点
 *   pNext/pPrev = 自身                    // 自环: 游离标记
 * ===================================================================== */
#define XC_SCH_TAKE_FIRST(phTCB)                        \
    do {                                                \
        (phTCB)->ListNode.pNext->pPrev = (phTCB)->ListNode.pPrev;  \
        (phTCB)->ListNode.pPrev->pNext = (phTCB)->ListNode.pNext;  \
        (phTCB)->ListNode.pNext = &(phTCB)->ListNode;   \
        (phTCB)->ListNode.pPrev = &(phTCB)->ListNode;   \
    } while(0)

/* =====================================================================
 * 任务插回就绪表尾(特化内联宏, 无函数调用, 无临时变量)
 * ---------------------------------------------------------------------
 * 输入: phReady = 就绪表根; phTCB = 要插回的任务(必游离/自环)
 * 前提(方案A保证):
 *   1. 任务节点必游离(自环) -> 无需先摘除, 直接覆盖指针;
 *   2. 表尾节点的 pNext 恒为 Root -> 无需读表尾的 pNext, 直接写 Root。
 * 步骤(直接用 phTCB 引用任务节点, 免临时变量):
 *   任务->pNext = Root                 // 任务成为新表尾(指向根)
 *   任务->pPrev = Root->pPrev          // 任务前驱 = 原表尾
 *   原表尾->pNext = 任务                 // 原表尾后继 = 任务(闭合)
 *   Root->pPrev = 任务                 // 根前驱 = 新表尾
 * 边界: 就绪表空时原表尾 == Root, 结果 Root->任务->Root(单节点表), 统一成立。
 * ===================================================================== */
#define XC_SCH_PUT_TAIL(phReady, phTCB)                 \
    do {                                                \
        (phTCB)->ListNode.pNext = (phReady);            \
        (phTCB)->ListNode.pPrev = (phReady)->pPrev;     \
        (phReady)->pPrev->pNext = &(phTCB)->ListNode;   \
        (phReady)->pPrev = &(phTCB)->ListNode;          \
    } while(0)
```



**收益**：让出任务每轮从约 28-42 周期降到约 10-16 周期。

### 5.3 编译优化

`armcc -O1` 可提升至 `-O2`（调度器无易错优化，安全）。

## 6. `pPrevReadyNode` 移除（简化）

### 6.1 恒等性证明

方案 A 下 `pPrevReadyNode` 的唯一赋值点 = 取任务时 `pIterator->pPrev`（表首节点的前驱）= **就绪表根**（环形链表不变量）；`XC_Sch_Init` 初始化为 `&ReadyList`；就绪表空时保持 `&ReadyList`。**恒等于 `&phXCOS->ReadyList`，字段冗余**。

### 6.2 引用点与改动

| 位置                            | 现状                                      | 改为                                          |
| ------------------------------- | ----------------------------------------- | --------------------------------------------- |
| `XC_TypeInternal.h` ~71 行      | 字段 `XC_ListNode_t* pPrevReadyNode;`     | 删除（XCOS_t 48→44B）                        |
| `XC_TaskInternal.h` ~97 行      | `MoveNodeAfter(pPrevReadyNode, …)`       | `MoveNodeAfter(&phXCOS->ReadyList, …)`       |
| `XC_Task.c` ~108 行 AddInternal | `InsertNodeAfter(pPrevReadyNode, …)`     | `InsertNodeAfter(&phXCOS->ReadyList, …)`     |
| `XC_Sch.c` Init ~193 行         | `pPrevReadyNode = &ReadyList;`            | 删除                                          |
| `XC_Sch.c` Start ~226 行        | `pPrevReadyNode = pIterator->pPrev;`      | 删除                                          |
| `XC_Sch.c` TimeSched ~79 行     | `MoveListToNodeAfter(pPrevReadyNode, …)` | `MoveListToNodeAfter(&phXCOS->ReadyList, …)` |

### 6.3 收益

```c
    for(;;) {
        /* 取任务: ListValid 锁外判断(中断仅通知类, 只加不减 -> 判断后不会变空) */
        if(XC_List_ListValid(&phXCOS->ReadyList)) {
            XC_Core_Lock(phXCOS);                    // 锁: 保护取任务链表操作 vs 中断 SendNotify 并发
            phTCB = XC_LIST_TO_TCB(XC_List_GetListStartNode(&phXCOS->ReadyList));  // 表首节点 = Root->pNext
            XC_SCH_TAKE_FIRST(phTCB);        // 摘除: 自环 => 游离标记
            phTCB->TaskState = XC_TASK_RUN;          // 任务状态: 运行
            XC_Core_Unlock(phXCOS);                  // 解锁: 运行阶段中断可正常直接操作

            /* 运行(锁外) */
            phTCB->fTask(phTCB);                     // 恒调当前层(顶层或子层)
            /* 同轮切父: 当前层完成(DONE)且栈非空时, 弹帧并立即运行父层 */
            while((phTCB->CorState == XC_COR_DONE) && (phTCB->CorDepth > 0U)) {
                XC_Task_PopFrame(phTCB);             // 出栈: 恢复父层入口+返回点
                phTCB->fTask(phTCB);                 // 同轮切父: 运行父层
            }
            /* 顶层 DONE 回落 READY(状态一致性) */
            if((phTCB->CorState == XC_COR_DONE) && (phTCB->CorDepth == 0U)) {
                phTCB->TaskState = XC_TASK_READY;
            }
            /* 归位(锁内): 仅游离(自环)任务插回就绪表尾 */
            /* 自环 = 运行中没被任何 API 移表(Yield/Leave/直接return);
             * 非自环 = 已被 Delay/Suspend/Reset/唤醒 API 移入对应表, 不干预 */
            if((phTCB->TaskState != (uint8_t)XC_TASK_VOID) &&   // 排除已移除任务
               (phTCB->ListNode.pNext == &phTCB->ListNode)) {   // 游离判定(自环)

                XC_SCH_PUT_TAIL(&phXCOS->ReadyList, phTCB);  // 插表尾(轮转)
                XC_Core_Unlock(phXCOS);
            }
        }
        /* 就绪表空: 直接跳过, 进入时间/事件/空闲处理 */
    }
```

## 10. 风险与注意事项

1. **实施顺序**：先落方案 A（主循环），再删 `pPrevReadyNode`，最后加优化宏——避免中间状态不一致；
2. **特化宏的前提**：`TAKE_FIRST` 依赖"表首前驱=Root"、`PUT_TAIL` 依赖"任务游离"——由方案 A 保证，但宏为手写链表操作，**必须经 8.2 全部测试验证**；
3. **Reset 后任务在表首**：`HandleReset` 插表首，任务非自环 -> 调度器不干预 -> 下轮优先运行一轮，随后正常让出（语义可接受）；
4. **中断路径**：取任务/插回在锁内（约 20-40 周期 <1us），中断期间 SendNotify 走异步路径，兼容现有锁模型；
5. **`pPrevReadyNode` 删除的兼容性**：该字段为内部结构，非公开 API，删除不影响用户代码。

## 13. 后继补充（2026-08-24）：归位状态一致性完善（状态管理遗漏）

> 本方案（取走任务 + 自环判定）实施后，内核深度审查发现**归位逻辑的状态管理遗漏**并已修复：
> 归位只处理 `CorState==DONE`，导致父层 `XC_Cor_Call` 让出后任务报 `RUN`；且"无条件置 READY"会覆盖
> 运行中被挂起任务的 `SUSPEND`，造成阻塞表僵尸。**本质**：状态置位应与"是否回就绪表"绑定，而非与 `CorState` 绑定。

### 13.1 问题现象

| 表现                | 状态    | 实际位置             | 后果                                    |
| ------------------- | ------- | -------------------- | --------------------------------------- |
| **A. 让出后报 RUN** | `RUN`   | 就绪表（已让出排队） | 状态误报，持续到下次调度                |
| **B. 阻塞表僵尸**   | `READY` | 阻塞表（被挂起）     | `Resume` 无法恢复，**任务永不再被调度** |

### 13.2 触发条件

**表现 A**（高频，纯嵌套用法即可触发）：

> 任务使用协程嵌套，父层在 `XC_Cor_Call()` 之后**没有紧跟 `XC_Cor_Delay`/`XC_Cor_Yield`**（例如父层连续两次 `XC_Cor_Call`、或 `Call` 后直接到 `XC_Cor_Leave`）。

**表现 B**（边界，依赖中断中 Suspend 挂起运行中任务；若 Suspend 不支持中断则此表现不可达——**表现 A 独立成立，不依赖此条**）：

> 任务运行期间被中断中的 `XC_Task_Suspend()` 移入阻塞表（`SUSPEND`），随后该任务执行到 `XC_Cor_Leave()`（`CorState==DONE`）让出。

### 13.3 根因分析

**背景**：`XC_Cor_Enter` 每次进入协程块时把 `CorState` 置为 `XC_COR_SUSPENDED`，只有执行到 `XC_Cor_Leave` 才置 `XC_COR_DONE`（挂起/Call/yield 经底层 `goto` 跳过 DONE 赋值）。

**本方案实施时的归位逻辑**：

```c
/* 状态一致性:顶层完成(DONE,无嵌套)后任务让出,状态应回落到就绪
 * (避免任务已让出却仍报 RUN,直到下次调度) */
if((phTCB->CorState == XC_COR_DONE) && (phTCB->CorDepth == 0U)) {
    phTCB->TaskState = XC_TASK_READY;          // ← 仅 DONE 才置 READY
}
/* 归位(锁内): 仅游离(自环)任务插回就绪表尾 */
if((phTCB->TaskState != (uint8_t)XC_TASK_VOID) &&
   (phTCB->ListNode.pNext == &phTCB->ListNode)) {
    XC_Core_Lock(phXCOS);
    XC_SCH_PUT_TAIL(&phXCOS->ReadyList, phTCB);
    XC_Core_Unlock(phXCOS);
}
```

**缺陷链路**：

1. 调度器 `TAKE_FIRST` 摘取任务后置 `TaskState=RUN`；
2. 父层执行 `XC_Cor_Call` → 入栈 + `COR_BreakLabel` 让出。此时 `CorState` 为 **SUSPENDED**（Enter 置的默认值，并非 DONE）；
3. 调度器回位判定：任务节点游离 → 插回就绪表尾，但 `CorState==DONE` 条件**不满足** → 不置 READY → `TaskState` 保持 **RUN** → **表现 A**；
4. **表现 B 的根源**："无条件置 READY"（只要 DONE 就置）**与链表位置解耦**——若任务运行中被中断 Suspend 移入阻塞表（`SUSPEND`），任务随后 `Leave`（DONE）时该语句会把状态覆盖为 `READY`，而节点仍在阻塞表 → **"在阻塞表却报 READY"**。此时 `Resume` 检查 `TaskState==SUSPEND` 失败、`EventSched` 只唤醒 `WAIT` 任务，任务**永久滞留阻塞表**（僵尸）。

### 13.4 影响与严重程度

**高**（表现 A 为高频路径）。

- 表现 A：任何"`Call` 后无 Delay/Yield"的嵌套父层任务，让出后到下次调度之间 `GetState` 误报 RUN；
- 表现 B：触发即造成任务永久丢失（僵尸），不可恢复。

### 13.5 修复方案（归位锁内置 READY，已实施）

删除 `CorState==DONE` 的无条件置位，将状态同步移入归位块（锁内、与链表插回原子）：

```c
/* 归位(锁内): 仅游离(自环)任务插回就绪表尾
 * 自环 = 运行中没被任何 API 移表(Yield/Leave/直接return);
 * 非自环 = 已被 Delay/Suspend/Reset/唤醒 API 移入对应表, 不干预;
 * 状态一致性: 游离任务让出后必然回就绪表, 状态同步为就绪(READY);
 * - 覆盖 DONE 让出(Leave): 原"仅 DONE 置 READY"逻辑;
 * - 覆盖 SUSPENDED 让出(父层 Call 后自然退出/子层 Call): 原逻辑漏置, 报 RUN;
 * - 不再无条件置 READY: 避免覆盖运行中被中断挂起(阻塞表)任务的 SUSPEND,
 *   造成"任务在阻塞表却报 READY"的僵尸状态(Resume 永远无法恢复) */
if((phTCB->TaskState != (uint8_t)XC_TASK_VOID) &&          // 排除已移除任务
   (phTCB->ListNode.pNext == &phTCB->ListNode)) {          // 游离判定(自环)
    XC_Core_Lock(phXCOS);                                  // 锁: 插回是链表写操作, 防中断 SendNotify 并发
    XC_SCH_PUT_TAIL(&phXCOS->ReadyList, phTCB);            // 插就绪表尾(轮转)
    phTCB->TaskState = XC_TASK_READY;                      // 状态一致性: 锁内同步(与链表操作原子)
    XC_Core_Unlock(phXCOS);
}
```

**变更要点**：
- 删除"`CorState==DONE && CorDepth==0` 无条件置 READY"；
- 状态置位改到归位插回块内（锁内、仅在任务确实回就绪表时）；
- 覆盖 DONE 让出（Leave）与 SUSPENDED 让出（父层 Call 后自然退出），且不再覆盖挂起任务状态。

### 13.6 验证（实测）
